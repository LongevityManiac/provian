# Auth Map

A **Provenance Envelope (PE)** is signed, hash-chained proof owned by its contributor. **PVT** is the currency on Base minted from witnessed work. The **relay** verifies and prices submitted evidence; a **witness** is something other than the actor that vouches for the act. **Basis points (bps)** express factors in ten-thousandths: 10,000 bps is 1.0×.

One page, every credential. Provian's relay speaks several credential types on purpose — each one is scoped to a distinct trust boundary, and the boundaries are never merged. This page maps each credential to what it unlocks, what it can never do, and where you get it.

> Rule of thumb: **wallet auth writes owner state; everything else can't.** The beneficiary link, the share, device ownership, and connection-token minting belong exclusively to the wallet owner's phone. No agent-side credential — API key, device key, or setup token — can ever reach them.

## The map

| Credential | Format on the wire | Where you get it | Unlocks | Never | Lifetime |
|---|---|---|---|---|---|
| **Wallet auth** (phone) | `Authorization: Bearer {payloadB64}.{hmacSignatureHex}` — request-bound HMAC token; payload carries `sub`, `device_id`, method, path, and body hash | Minted per request by the Provian app from the device's stored auth secret | Everything wallet-side: owner-state writes (the beneficiary link, the share, device ownership), connection-token minting, user data, the phone's daily PE batch (`POST /v1/meter/batch/mobile`) and proofs (`GET /v1/meter/mobile/proofs`), `POST /v1/payout/mobile`, plus the wallet half of every dual-auth read | Nothing — this is the root credential; but each token is single-use, bound to one request | ~90 seconds, single-use (replay-detected) |
| **Agent API key** | `Authorization: Bearer {pvn_live_…}:{pvns_…}` | Self-signup: durably store one registration/agent/key identity, then `GET /v1/agent/wallet/challenge` → sign locally → `POST /v1/agent/wallet/create`. An ambiguous same-key retry returns the same wallet and replaces only the lost API credentials; superseded credentials are invalidated | The agent-wallet lane: wallet self-ops (balances, inbox, transfer/burn/swap record, on-demand payout `POST /v1/payout` (paid over x402), device-invite, burn-to-present, human-approval requests; `link-human` / `unlink-human` only with the linked human's EIP-191 consent signature in the body), Commons institutions (escrow / promises / pools / bonds / court / webhooks / directory), the Commons hiring board (`/v1/commons/jobs`), external-address challenge+verify, Commons writes (behind a live speech window), headless device registration, Genesis status, key/address rotation (`POST /v1/agent/wallet/:wallet_id/rotate-key` — ownership + dual proof-of-possession from old and new keys, 1 per 24h) | Anything wallet-auth-only (owner-state writes — the beneficiary link, the share, device ownership); any other wallet's resources (every `:wallet_id` route re-checks ownership) | No expiry; initial-registration credential recovery can replace a lost API credential for the same key; dies with wallet status |
| **Device key** | `Authorization: DeviceKey {pdk_…}:{pds_…}` (or `Basic` base64; Secure-Enclave devices use `DeviceSignature {device_id}` + `X-Provian-Signature`) | `POST /v1/devices/register` (returned **once**), authenticated by wallet auth, a setup token, or an agent API key | The device's daily PE batch `POST /v1/meter/batch` (the observer's lanes: observation-lane action types, plus a never-seen type an observer plugin witnessed; body-bound —), `GET /v1/meter/tip`, `GET /v1/meter/proofs`, the sealed mailbox (`GET /v1/meter/mailbox`), `GET /v1/devices/me`, git-witness connect flows | Everything else: no policy, no wallets, no transfers, no Commons writes, no device management | No expiry; revocable; no per-user PE volume cap |
| **`agent_device_registration` setup token** | `Authorization: Bearer {64-hex token}` — exactly once | Emailed one-time line, minted by `POST /v1/agent/wallet/:wallet_id/device-invite` (agent API auth) or `POST /v1/relay/connect/email-command` with `kind=agent_device` (linked human's wallet auth). Never returned over HTTP | Exactly one thing: `POST /v1/devices/register` for one agent-owned device | Everything else — never key rotation, transfers, link-human, or governance; not honored on any other route | 1 hour, single-use, burned transactionally |

## Notes that keep the boundaries honest

- **"Dual auth" means wallet auth OR agent API key.** PVT allocation, the devices/attribution family, and `GET /v1/trust/profile/:address` accept either.
- **The human `device_registration` setup token is a different animal** from the agent one: it is honored (once) by the global wallet-auth middleware, sets the human user, and is refused on every route but `POST /v1/devices/register`. The agent variant is honored by a dedicated middleware on that same route only and sets the agent wallet. Don't conflate them.
- **Agent-owned devices register at the software tier.** The relay forces `software` attestation for agent devices before signing-method selection; a per-PE `hardware_witness` report signed by a non-actor key is a separate evidence path, not a device tier. The registration path deliberately supplies no device anchor for the agent-owned `device_register` setup PE; that identity proof has no separate mint because the action-policy matrix's `device_register` row is `record_only` (weight 0) for every owner — the missing anchor is not the cause (Security Invariant #9).
- **x402 uses none of these.** The agent pays HTTP 402s from its own sovereign wallet with its own key, agent-side in the SDK — no relay credential in the payment path. (The relay's own on-demand payout, `POST /v1/payout`, takes the agent API key and charges its flat $1 USDC service fee over x402.) The SDK records no `x402_payment` PE of its own; the chain watcher witnesses the settlement. `POST /v1/pe/submit-sovereign`, authenticated by an EIP-191 signature from the agent's own EOA, records only a known compute/work-family occurrence carrying an admitted non-actor `hardware_witness`; it refuses `x402_payment`, `link_spend`, and any body with no hardware witness.
