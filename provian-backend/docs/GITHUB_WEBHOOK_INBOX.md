# GitHub webhook push delivery

Ingress verifies the GitHub HMAC, commits an encrypted durable receipt, and enqueues an OIDC-authenticated Cloud Task before acknowledging success. The task carries only the receipt identifier. Pending receipts never expire. A dispatch failure returns a retryable response and retains the receipt; redelivery reuses it. Completed redeliveries do not enqueue work.

The `provian-github-webhooks` Cloud Tasks queue dispatches immediately to `/v1/internal/tasks/github`. Empty queues make no worker requests. The worker retains the existing transactional lease, frozen PE input and deterministic PE identity. An unfinished, backed-off or leased receipt returns HTTP 503 so transport retries continue. Only a completed receipt is acknowledged. Completed receipts discard payload and prepared PE input and retain delivery deduplication metadata for 90 days.

Accepted PR presentations dispatch a continuation through the same queue. It waits for burn finality while its request is active, then reconciles clearance and the contributor comment/check/label. It never creates merge approval. A qualifying owner review dispatches via its own webhook receipt; transient merge refusal keeps that receipt retrying. Existing author identity, payment and current-head review checks remain authoritative.

`provian-github-pr-gates` runs once daily at 04:18 UTC as the lost-event net: it redispatches due inbox rows and pending presentations and reconciles PRs and previously recorded approval intents. It is never the normal delivery, clearance or approval path. Daily task-name generations permit recovery after transport retention expires; pending receipt storage remains indefinite. The former one-minute webhook scheduler is deleted.

Provision with `bash scripts/configure-github-push.sh` from the backend directory before deployment. The script enables Cloud Tasks, configures durable retries, grants queue-scoped enqueue and Service Account User only on the dedicated `provian-github-worker` identity, and sets the daily recovery schedule. Deploy the worker before deleting the old poll with `--retire-poll`. The queue overrides every task target to the exact worker URL, method and dedicated OIDC identity. Only that route accepts this account, with its own route-bound audience and no scheduler-secret fallback. The runtime has no Service Account User binding on the scheduler account. Resume the queue at least one minute after its routing configuration changes.
